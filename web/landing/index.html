Your customers send files. Your app gets webhooks.

RelayStack gives each of your customers an inbox for CSV files. Every row is checked against your schema, and the valid records reach your app as signed JSON webhooks, retried until they land and replayable afterwards.

The plumbing you don’t have to build

Taking a file from a customer sounds like an afternoon. It turns into a queue, a parser, retry logic, a replay tool and an audit trail, none of which is your product.

  • A place for files to land

    Each customer gets an inbox they can upload to over HTTPS. SFTP is next.

  • Parsing that survives real exports

    Files are streamed with hard limits on size, row length and column count, so a huge or broken export can’t take your service down.

  • Errors your customers can fix

    Every rejected row comes back with its row number and a plain reason. The valid rows still go through.

  • Delivery you don’t have to watch

    Webhooks are retried with backoff when your endpoint is down, parked when retries run out, and replayed with one click.

  • Duplicates that are easy to drop

    Delivery is at-least-once. Each batch keeps the same webhook-id across retries and replays, so your handler can ignore repeats.

  • A record of what happened

    Every file, record batch and delivery attempt is logged and visible in a dashboard, and every webhook is signed so you know it came from RelayStack.

How it works

You set up the inbox once and handle the webhooks. Your customers only ever see an upload address.

  1. Describe the file

    Create an inbox with the columns you expect, their types, and where valid records should go.

    POST /v1/inboxes
{
  "name": "timesheets",
  "destination_id": "your webhook endpoint",
  "schema": { "columns": [
    { "name": "employee_id", "type": "string", "required": true },
    { "name": "hours_worked", "type": "decimal", "required": true },
    { "name": "period_end", "type": "date", "required": true }
  ] }
}

  2. Give your customer the upload address

    They upload whenever their system exports. Uploads are idempotent, so a retried upload never creates a duplicate.

    POST /v1/inboxes/{inbox_id}/files
Content-Type: text/csv
Idempotency-Key: halden-2026-11-15

(the CSV, streamed as the request body)

  3. Handle the webhooks

    Verify the signature, process the records, return a 2xx. Rejected rows are listed against the file for you or your customer to review.

    webhook-signature: v1,base64(
  HMAC-SHA256(secret, "{id}.{timestamp}.{body}")
)

Return 2xx when processed. Anything else is retried.

After files: APIs that never got webhooks

Some systems only offer an API you have to keep asking. RelayStack will poll it on a schedule, compare what it sees with last time, and send you only the records that are new or changed, through the same signed, retried delivery. 

Every 15 minutes:
GET https://legacy-hr.example/api/employees

poll.record.created   E1004  Morgan Ellis
poll.record.updated   E1001  department ENG → OPS
