# Domain model

Every tenant-owned row carries `organization_id`. Cross-table references are **composite foreign keys that include
`organization_id`** (and project/environment where relevant), so the database itself prevents a row from pointing at
another tenant's row. Ids are UUIDv7 (time-ordered), generated by the application.

```
Organization 1─* Project 1─2 Environment (development | production)
                                 │
     ┌───────────────┬───────────┼──────────────┬───────────────┐
  ApiKey     WebhookDestination  Inbox ─────┐   PollSource      UsageRecord
  (scopes)   (encrypted secret)  (schema)   │   (experiment)
                     ▲             │        │        │
                     │           File ──────┘        │
                     │             │ └─ ValidationError
                     │             ▼                 ▼
                     │           Event (source = file or poll source; exact signed body)
                     │             │
                     └──────── Delivery ── DeliveryAttempt
                                   └─ replay_of → Delivery
Job (process_file)          AuditEntry          PollObservedRecord
```

| Entity | Key fields | Notes |
|---|---|---|
| Organization | name | The tenant boundary. RLS key. |
| Project | name | Groups environments. |
| Environment | kind | `development` or `production`. Every resource below is environment-scoped; a dev key cannot see prod data. |
| ApiKey | prefix, secret_hash, scopes, expires_at, revoked_at | Bound to one environment. Secret never stored. |
| WebhookDestination | url, signing_secret_ciphertext, timeout_seconds, max_attempts, enabled | Secret encrypted, bound to the organization. |
| Inbox | validation_schema (jsonb), destination_id, max_file_bytes, retention_days | The validation configuration lives on the inbox and is versioned with it. |
| File | storage_key, sha256, size, status, row counts, error, idempotency_key, expires_at | `received → processing → completed / failed → expired` |
| ValidationError | row_number, column, code, message | At most 1,000 stored per file; all rejected rows are counted. |
| Job | kind, subject_id, status, attempts, run_after, locked_by, locked_until | One active job per subject (partial unique index). |
| Event | source_kind, source_id, dedupe_key, type, body, expires_at, purged_at | `body` is the exact signed bytes, nulled when purged. |
| Delivery | event_id, destination_id, status, attempt_count, next_attempt_at, lease, replay_of | The outbox row. `failed` = dead letter. |
| DeliveryAttempt | attempt_number, outcome, status_code, error (redacted), bytes, duration | Unique per (delivery, attempt). |
| UsageRecord | metric, quantity, subject_id | Append-only. |
| AuditEntry | actor, action, target, remote_ip, details | Append-only for the API role. |
| PollSource / PollObservedRecord | url, record_id_field, interval / record_key, content_hash | Phase 0 experiment. |

**Failed deliveries** are not a separate table: they are deliveries with `status = 'failed'`, listed with
`GET /v1/deliveries?status=failed`. This keeps one state machine and one replay path.

## State machines

```
File:      received ─► processing ─► completed ─► expired
                             └─────► failed ───► expired
Job:       pending ─► running ─► succeeded
              ▲          │ ├────► failed (attempts exhausted or permanent error)
              └──────────┘ └ lease expiry (crash) makes it claimable again
Delivery:  pending ─► in_flight ─► succeeded
              ▲           │  └───► failed (permanent response, or attempts exhausted)
              └─ retry ───┘  lease expiry (crash) makes it claimable again
           replay of a terminal delivery = new pending delivery with replay_of set
```

## Tenant isolation guarantees

| Guarantee | Mechanism | Status |
|---|---|---|
| A row cannot reference another tenant's row | Composite FKs incl. `organization_id` | Implemented |
| API cannot read or write another organization's rows | Postgres RLS on every tenant table for `relaystack_app`; fails closed if the session tenant is unset | Implemented, tested with raw SQL |
| API cannot read another environment's resources | EF query filters on organization + environment | Implemented, tested |
| API cannot read API keys at all | No grants; lookup through `auth_lookup_api_key()` SECURITY DEFINER | Implemented, tested |
| Object keys are always inside the tenant prefix | `TenantObjectKey` built from ids only, re-validated on read | Implemented, tested |
| Secrets cannot be moved between tenants | AES-GCM associated data includes the organization id | Implemented, tested |
| Worker cannot read or write outside the item it is processing | Same RLS policy as the API role. Cross-tenant discovery only through four SECURITY DEFINER claim functions that lease and return due rows. Each item is handled in a context scoped to its organization; unscoped worker connections see nothing (ADR-014) | Implemented, tested with raw SQL and EF; mutation-checked |
| Claim functions cannot be misused by the API | Executable only by `relaystack_worker`; inputs clamped | Implemented, tested |
| Noisy-neighbour isolation | Per-key rate limits and per-org delivery concurrency (soft) | Partial; per-tenant quotas outstanding |
| Physical isolation (separate DB/bucket per tenant) | Not offered | Outstanding (enterprise option) |
